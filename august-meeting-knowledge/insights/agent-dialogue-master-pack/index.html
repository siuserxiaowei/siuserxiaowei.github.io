02

综合章节

洞 01

一、先读边界：三十页不等于三十份完整纪要

当前公开集合有三十页，其中二十六页标记为 partial、四页标记为 insufficient、没有一页标记为 complete。partial 只表示页面提炼了有公开锚点支持的部分，不代表整场录音连续、所有议题都被覆盖或观点已经核实；insufficient 只支持“现有材料不足以复原内容”这一覆盖结论，不能被标题、常识或其他相邻分段补成实质讨论。Agent 开始回答前要读取每页的 contentStatus、confidence、limitations、claimsToVerify 与公开证据锚点，并把支持范围写进来源账本。跨页重复出现的说法可能来自同一开放办公现场、同一参与者或相邻录音分段，不能自动当作多份独立证据。

可以带走

  • 固定边界为二十六页 partial、四页 insufficient、零页 complete，任何摘要都不得升级这个状态
  • partial 页面按具体主张取证，不把页面存在等同于整场会议完整
  • 四个 insufficient 页面只用于训练停止推断与补证流程，不为主题结论投票
  • Agent 的归纳、改写和联想属于新生成内容，绝不自动成为会议事实
洞 02

二、输入授权与最小化：先决定什么不进入上下文

每次对话先写输入清单：本次目的、允许来源、允许字段、可见范围、保留方式和任务结束后的处理。默认只接收公开会议页、这份综合页、已脱敏知识卡、用户明确授权且完成最小化的项目材料，以及为核验易变事实而选取的当前权威来源。不要索取或粘贴私有逐字稿、访问令牌、账号凭据、内部资源链接、未公开客户资料、个人联系方式、详细位置、私人财务或可识别关系；“模型需要更多上下文”不是扩大收集的理由。若输入意外包含敏感值，Agent 应停止处理、避免回显，要求用户在来源侧删除或泛化后再继续。

可以带走

  • 授权按任务而非按资料库整体授予，目的改变就重新确认范围
  • 只给完成当前问题必需的字段，优先聚合、去标识或公开版本
  • 敏感输入进入上下文前就应被排除，不能依赖输出阶段再脱敏
  • 发现不应处理的内容时，返回风险类别和安全替代，不复述原值
洞 03

三、来源账本与 evidence status：让每句话知道自己从哪里来

来源账本按“主张”而不是按“文件”记账。每条记录至少包含 claim、claimType、sourceRefs、contentStatus、confidence、supportScope、evidenceStatus、limitations、counterEvidence 与 nextCheck。claimType 区分公开页支持、会上观点、跨页综合、外部当前事实、用户项目观察、假设、决策和未知；evidenceStatus 使用 supported、partial、conflicting、unverified、insufficient 或 superseded，避免把不同性质压成一个分数。公开 slug 与公开锚点可以用于追溯，但私有标识不得进入账本。一个页面只支持它实际陈述的范围；跨页综合必须列出推导过程，外部事实必须另附当前来源，用户项目事实则要绑定可检查产物。

可以带走

  • 证据类型回答“这是什么话”，证据状态回答“它目前被支持到什么程度”
  • 多个弱来源不会因数量自动变成强事实，先检查是否同源、重复或相互引用
  • 来源支持原句 A 时，Agent 不能无标记地扩写成因果更强、范围更大的 B
  • 缺少来源、支持范围或反证入口的结论只能进入待核验区，不能进入事实区
洞 04

四、知识卡规范：把可复用观点做成原子单元

一张卡只承载一个可判断的主张或一个明确未知，不把整场会议压进长摘要。最小字段包括 cardId、title、claim、claimType、evidenceStatus、confidenceReason、sourceRefs、publicAnchors、supportScope、reasoning、boundary、counterEvidence、conflictsWith、unknowns、decisionImpact、suggestedTest、visibility、version、revisionReason、reviewTrigger 与 supersedes。来源字段只引用公开 slug、公开锚点或用户批准的外部引用；reasoning 明确写出从证据到结论的推导，boundary 写不适用条件。实验结果、团队决定和 Agent 建议各自建立新卡，不能覆盖来源卡，也不能把建议改名为“会议结论”。

可以带走

  • 原子卡的判断标准是：脱离长上下文后仍能知道它说什么、凭什么、不能说明什么
  • 事实、观点、综合、假设、实验结果与决定分卡保存，避免后来检索时失去归属
  • 更新使用新版本和 supersedes 关系，不静默改写旧卡造成历史漂移
  • 没有 supportScope、boundary 和 reviewTrigger 的卡不进入长期知识区
洞 05

五、上下文打包、分块与版本：按决策单元喂给 Agent

上下文包按八层组织：任务与可观察产物、授权边界、来源账本、选中的原子卡、用户当前项目事实、冲突与未知、工具和预算权限、输出与回写规则。分块以一个问题、一个主张或一条决策链为单位，不按固定字符数机械切断；每块都携带 packageId、cardId、version、来源状态与边界。检索时先取与当前决策直接相关的卡，再取反证卡和限制卡，最后才取邻近主题；上下文超限时优先保留状态、来源、边界和未知，不能只留下流畅结论。更新采用差异包：说明新增、修订、废止及原因，并固定本轮实际使用的卡版本。

可以带走

  • 先固定问题与产物，再选卡；不要先倾倒资料再让 Agent 猜任务
  • 每个分块自带来源状态与边界，脱离原文件后仍可审计
  • 检索同时召回支持、反证和限制，防止只找同意当前假设的材料
  • 版本必须随回答保存，否则同一提示词在知识库变化后无法复盘
洞 06

六、提问模板：从复述升级为判断、区分与补证

高质量提问由六个槽位组成：我要做的决定、当前对象与环境、允许使用的来源、必须区分的证据类型、期望产物、权限与停止条件。先问“哪些公开页具体支持这句话”，再问“相反证据、适用边界与未知是什么”，最后问“哪一个最小动作能改变决定”。理解型任务要求 Agent 并列复述与局限；比较型任务要求统一维度且不补齐缺失值；决策型任务要求输出继续、受限试验、补证或停止；执行型任务还要列工具、影响、回滚与审批。若问题只能靠私有材料或高风险信息回答，应把结果标为无法从当前授权范围确定。

可以带走

  • 把“总结一下”改写成决定、证据范围、产物和停止条件
  • 要求 Agent 主动给出反证与未知，而不是只生成支持当前方向的理由
  • 不同方案必须用同一组维度比较，缺失值保持未知，不做语言补齐
  • 无法改变行动的泛泛洞察降级，优先生成能触发补证或实验的问题
洞 07

七、五类场景追问：同一知识底座，不同验收问题

创业场景追问真实用户、当前替代、愿付代价、获客—交付—复购—现金链、合规与 No-go；工程场景追问任务契约、规格版本、依赖图、测试工件、运行证据、发布与恢复；内容场景追问目标人群、可证明承诺、素材权利、许可承接、履约容量和完整漏斗；硬件与语音场景追问真实环境、设备版本、端云链路、质量与延迟预算、授权数据、实机长尾、供应和售后；微信生态场景追问用户任务、主体与应用类型、当前官方规则、最小权限、留存与支付，并把可被 Agent 调用的能力写成授权、输入输出、拒绝、幂等、回执、撤销和人工接管契约。相同的会议观点在不同场景下可能产生不同补证动作，不能复制同一个答案。

可以带走

  • 创业先证明价值闭环，工程先证明交付闭环，两者不能用同一张完成表
  • 内容增长要与真实履约相连，曝光不能独立代表业务结果
  • 硬件与语音必须回到真实设备和授权数据，演示效果不是系统验收
  • 微信平台能力、规则与费用属于易变事实，执行前另查当前官方来源
洞 08

八、冲突与未知：不投票、不取平均、不让 Agent 偷填空

冲突视图并列 claimA、claimB、各自来源、状态、适用条件、可能同源、决策影响与最小区分证据。先判断冲突来自目标不同、口径不同、环境不同、时间变化、样本偏差，还是确实互斥；没有区分证据就保留两个分支。未知也要建卡，写清它阻断哪项决定、为什么当前资料无法回答、最小补证动作和何时可以忽略。会议中反复出现的模型、价格、性能、市场、平台、供应或商业数字一律保持会上观点或待核验，除非另有当前权威来源或项目实测。

可以带走

  • 跨页一致只代表值得验证，不自动代表事实或共识
  • 冲突先找条件和口径，再决定能否合并；不能用多数票消除少数证据
  • 未知是知识库的一等对象，应能被检索、分配和关闭
  • 对高影响决策，无法区分冲突本身就是暂停或缩小实验的理由
洞 09

九、从洞察到实验：每次对话只推进一个可逆问题

Agent 不以“给出更多建议”为终点，而把一条尚未证实的洞察改写为实验卡：决策、假设、基线、目标用户或系统、固定输入、唯一主要变量、权限与预算上限、负责人角色、可观察成功与失败信号、证据产物、停止条件、回滚方式和复盘触发。实验结果建立项目观察卡，明确环境、版本和偏差；只有当结果通过人类验收，才能影响项目决定，仍不能倒写成会议事实。无法定义用户价值、合法输入、可观察结果、责任人或恢复路径时，输出应是补证或 No-go，而不是扩大并发和功能。

可以带走

  • 一轮只改变一个决定性变量，使结果能够解释
  • 成功标准、失败信号与停止条件在执行前写下，避免事后改口径
  • 实验必须生成可检查工件，而不是只留下 Agent 的自我评价
  • 结果回写为项目证据，与会议来源卡保持不同 claimType
洞 10

十、工具调用、审批与停止：能力越强，控制面越具体

工具计划先列动作、对象、环境、所需权限、外部影响、成本上限、验证、撤销与负责人。读取公开页、检索已授权知识卡和生成草稿属于低影响动作；写入共享知识库、修改代码或创建可恢复的隔离产物需要明确文件边界与差异检查；对外发布、付费、采购、权限变更、生产写入、删除或覆盖、不可逆迁移、客户或个人数据处理、健康与食品建议、真实设备高影响控制均需人类在执行前审批。出现未授权输入、只能靠凭据继续、目标或对象不清、无回滚、成本无上限、关键规则未核验、证据冲突影响安全，或连续失败无法解释时立即停止，并保留已完成工件和恢复说明。

可以带走

  • 通用授权不能替代对高影响动作的对象、后果和恢复核对
  • Agent 只描述需要的权限类型，不索取、保存或回显实际凭据
  • 高风险动作必须由人确认，审批记录与执行结果进入回写包
  • 停止不是失败隐藏，而是有原因、证据、恢复位置和下一步的正式状态
洞 11

十一、回写、更新与失效：让知识库记住变化而非只记住答案

每轮对话最后输出回写补丁，而不是直接重写旧笔记。补丁分为新增卡、修订卡、冲突卡、未知卡、实验结果、决定、废止关系与待复核项；每项说明 revisionReason、基于哪些来源、改变了什么、没有改变什么、谁负责核对以及什么条件触发重审。Agent 生成的摘要先进入 draft，只有人类核对来源账本和边界后才能进入 curated；外部规则、价格、模型能力、平台接口和供应状态设置短复核周期或事件触发，稳定原则则在出现反例、项目结果或来源状态变化时复核。检索索引与正文版本一起更新，旧链接可追溯，不删除曾影响决策的历史版本。

可以带走

  • 回答、卡片和索引是三种工件，三者版本要能对应
  • draft、curated、superseded 与 unknown 分开，避免草稿混入可信知识区
  • 更新说明同时记录新增证据与未解决边界，不用新结论掩盖旧冲突
  • 易变事实按事件触发复核，会议来源状态改变时重新计算受影响卡片
洞 12

十二、使用示例：评估“把语音能力接入微信小程序”

示例请求不代表会议决议：用户希望判断一项语音能力是否进入小范围微信产品试验。Agent 先在来源账本记录，语音链路与场景验收由相关 partial 页面支持，小程序真实用户、授权与上线门禁也由相关 partial 页面支持；具体用户需求、当前平台规则、设备表现、素材权利和预算仍未知。它不把两组方法拼成“项目已可上线”，而输出“补证”：先从当前官方材料核对主体、权限与接口边界；选一个真实用户任务和一批明确授权的测试素材；在隔离环境固定应用、模型、设备和提示版本；记录任务完成、分段延迟、识别与合成缺陷、拒绝和人工接管；任何对外发布、真实用户数据接入、付费或生产写入前单独审批。结果回写为项目实验卡，来源卡保持不变；若权利不清、关键路径无法验收或无恢复方式，则停止。

可以带走

  • 示例先给证据与未知，再给状态，不从两个主题页拼出虚假的确定性
  • 平台规则用当前权威来源补证，会议口述只用于提出检查项
  • 语音效果在授权素材、真实设备和完整用户旅程中验收
  • 回写的是实验结果与决定，不把后来发生的结果倒灌为会议事实
03

道 · 法 · 术 · 器 · 势

  1. 道01

    个人知识库的目的不是让 Agent 显得知道更多，而是让缺席者在不越权、不伪造确定性的前提下理解问题、形成判断并对后果负责；来源忠实、用户价值和人类责任是不可被工具替代的底线。

  2. 法02

    采用“最小授权 → 来源账本 → 原子知识卡 → 冲突与未知 → 场景追问 → 最小实验 → 人类验收 → 版本回写”的循环；每一环都保存状态、支持范围、反证和停止条件。

  3. 术03

    用六槽提问、八层上下文包、按决策单元分块、支持与反证共同检索、五场景追问、单变量实验卡和差异回写补丁，把一次对话变成可检查的知识工作。

  4. 器04

    公开静态页、个人笔记库、检索索引、版本控制、Schema 校验、权限系统、测试环境、日志与审批记录共同承载闭环；器负责保存和执行，不负责定义方向，也不自动赋予事实地位或操作权限。

  5. 势05
