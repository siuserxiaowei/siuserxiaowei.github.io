洞 01

先看图例：这是证据关系图，不是因果定律

本图只使用三十个已脱敏公开页。二十六页为 partial，表示页面保留了可定位、可公开、可迁移的部分内容，但不能代表完整议程、全体共识、事实已核验或行动已完成；四页为 insufficient，只能说明转写为空、覆盖稀疏、来源不明或无法复原，因而只挂在“证据缺口”和“停止条件”节点。图中的箭头表示一种需要在具体项目中检验的有向约束、前置、反馈或门禁关系；多个页面都提到两个概念，只能增加“值得检查”的理由，不能自动证明前者导致后者。涉及采购、上线、合同、合规、健康、食品、生产数据或对外承诺时，应回到关联单页查看状态、锚点、局限和待核验主张，再补当前权威材料与真实运行证据。

洞 02

十一张核心节点卡：先统一词义，再连接箭头

证据治理是对主张的来源、状态、更新时间、适用范围和反证进行管理；真实任务是某类用户在具体触发时刻要完成、且能观察结果的工作；任务契约把输入、版本、范围、权限、产物、质量、预算、失败处理和责任写清。端到端验收检查真实用户是否走完整旅程，不以局部组件成功替代交付。可靠性关注在代表性负载和异常条件下持续完成任务；权限限定谁能读、写、批准和撤销；数据权利回答材料能否被收集、加工、训练、共享、商业化和保留。增长漏斗把触达追到首次价值、付款、交付、复访或复购；单位经济把完整收入与获客、模型、人工、失败、退款、售后和风险成本放在同一口径。恢复要求系统能定位、回滚、续传、降级、重放或从备份恢复；停止条件则规定何时不再总结、发布、收费、自动执行或继续投入。

可以带走

  • 节点不是口号：每个节点都应对应一张可检查的记录、一位责任人或一个可观察结果。
  • 端到端验收、可靠性和恢复互有关联，但分别回答“是否完成”“能否持续完成”“失败后能否回到安全状态”。
  • 权限回答技术与组织上的允许范围，数据权利回答材料使用是否合法、合约是否允许；二者不能互相代替。
  • 增长漏斗描述行为路径，单位经济描述完整经营结果；高流量不能直接升级为正利润。
  • 停止条件不是悲观结论，而是保护证据、用户、现金、数据和恢复能力的控制节点。
洞 03

主干一：从证据治理走到端到端验收

八月材料反复暴露一种交付错位：标题、演示、运行提示、CI 绿灯、接口返回、Agent 自报完成和真实用户取得结果，属于不同证据层。主干的第一段因此从证据治理开始，先找到需要验证的真实任务，再把它写成任务契约，最后用端到端验收检查用户可见结果。箭头不是说有了前一项就必然产生后一项，而是提醒每次升级都必须带着来源、状态和失败样本。

可以带走

  • 起点：证据治理 → 关系：筛选并限定 → 终点：真实任务 → 为何：来源、样本与状态决定一个需求究竟来自用户行为、会上经验还是团队想象 → 边界：公开页没有完整用户研究，会议中反复出现的主题也不能替代目标用户验证。
  • 起点：真实任务 → 关系：定义输入与完成标准 → 终点：任务契约 → 为何：只有具体触发、输入、产物和可观察结果，Agent 与人才能对同一件事负责 → 边界：任务仍可能因环境、用户差异或新证据变化，契约需要版本化而非一次冻结。
  • 起点：任务契约 → 关系：提供验收基准 → 终点：端到端验收 → 为何：范围、版本、权限、产物和失败处理若未写清，局部成功很容易被误报为完整交付 → 边界：契约本身不是执行证据，仍需代表性用户、真实环境和异常路径的结果。
  • 起点：端到端验收 → 关系：回写失败样本与证据状态 → 终点：证据治理 → 为何：注册、支付、路由、输出、交接等断点会修正原先对任务与系统的判断 → 边界：一次通过或失败只覆盖当时版本、样本和环境，不应外推为永久结论。
洞 04

主干二：数据权利和权限是任务之前的边界

多场讨论涉及企业连接器、客户知识、语音、内容素材、公共数据、科研数据、账户资产和生产系统。公开材料能够支持的共同底线是：可访问不等于可使用，技术能调用不等于拥有授权，授权一次也不等于可以无限保留或转作其他用途。应先为数据权利建立用途与期限，再把它落实为最小、短时、可撤销、可审计的权限；高影响写入、付费、发布、删除和对客承诺继续保留人工批准。

可以带走

  • 起点：数据权利 → 关系：限定合法输入与允许用途 → 终点：任务契约 → 为何：训练、检索、分析、共享和商业化对同一材料可能需要不同授权 → 边界：本图不提供任何地区或行业的法律结论，实际用途需核对当前规则、合同和专业意见。
  • 起点：数据权利 → 关系：约束可授予范围 → 终点：权限 → 为何：没有来源、用途、保留期和转授权依据时，即使系统能够读取也不应开放给 Agent → 边界：技术访问控制不能补救无效授权，书面授权也不能替代最小权限和安全测试。
  • 起点：权限 → 关系：控制执行半径 → 终点：任务契约 → 为何：明确读、写、批准、撤销、预算和时间范围，才能避免一句模糊指令扩张为高影响操作 → 边界：权限配置会漂移，必须用低权限身份实测并保留审计，而不能只相信文档。
  • 起点：权限 → 关系：提供可安全复验的环境 → 终点：端到端验收 → 为何：真实旅程必须验证普通用户、管理员、服务账户与人工审批点是否各自只能完成被允许的步骤 → 边界：高权限测试通过不能代表目标角色可用，测试凭证也不得进入公开会议知识。
  • 起点：端到端验收 → 关系：暴露过度收集与越权路径 → 终点：数据权利 → 为何：完整旅程会显示哪些字段实际被读取、保存、传输或用于新的目的 → 边界：功能测试不能单独证明合规，还需数据清单、授权记录、保留策略与独立审查。
洞 05

主干三：验收之后还要经过可靠性与恢复

服务启动、模型下载、接口偶尔成功、硬件编译、脚本跑完或页面出现，只能证明局部状态。八月的网关错误、限流、配置覆盖、长任务中断、上传不完整、硬件接入困难和数据库误操作案例共同提示：交付需要在代表性负载、弱网、权限差异、依赖故障和人为误操作下继续可观察；失败时还要有队列状态、幂等、备份、回滚、降级、断点续传和具名升级路径。这里的共同性是工程审查框架，不是对任何具体故障根因的认定。

可以带走

  • 起点：端到端验收 → 关系：提供真实链路与失败样本 → 终点：可靠性 → 为何：只有穿过登录、计费、路由、依赖、产物和交接，才能发现局部测试没有覆盖的长尾 → 边界：验收样本若过窄、环境过理想或由开发者代操作，可靠性判断仍会偏高。
  • 起点：可靠性 → 关系：要求失败可定位且可逆 → 终点：恢复 → 为何：重试、回滚、降级、续传和备份只有在故障状态可观察时才不会扩大损害 → 边界：重启后恢复、无限重试或偶然成功不能单独证明根因，也不能代替恢复演练。
  • 起点：恢复 → 关系：把系统送回可复验状态 → 终点：端到端验收 → 为何：恢复完成的定义应是关键用户旅程重新通过，而不是进程重新启动或文件重新出现 → 边界：恢复点可能丢失最新数据或改变外部状态，需要明确可接受数据损失、时间目标和补偿责任。
  • 起点：任务契约 → 关系：预先声明故障预算和升级点 → 终点：恢复 → 为何：任务开始前写明超时、重试上限、检查点、人工接管和回滚对象，可防止 Agent 在失败中无限扩张 → 边界：探索任务可能无法预知全部故障，但仍应有时间、成本、权限和不可逆操作上限。
  • 起点：权限 → 关系：限制恢复操作的破坏半径 → 终点：恢复 → 为何：备份读取、生产切换、删除和回滚都可能造成二次事故，应采用分权、复核和短时授权 → 边界：紧急场景是否允许破窗操作需由组织预先制定并审计，本页不替代运行手册。
洞 06

主干四：增长漏斗必须连接单位经济和交付

内容、开源、短视频、小程序、社群、活动、搜索与私域都是获得证据的入口，不是经营结果。跨页可迁移的路径是把目标用户从触达追到首次价值、有效咨询、付款、交付、退款、复访或复购，再把模型、云资源、内容、渠道、人工、失败重做、支付、供应、售后和风险准备放入同一成本口径。漏斗与单位经济只在来源、分母、时间窗和归因规则清楚时有意义；会上的流量、价格、成本和收益故事均不能作为行业基准。

可以带走

  • 起点：真实任务 → 关系：规定漏斗中的首次价值事件 → 终点：增长漏斗 → 为何：只有知道用户来完成什么，触达、注册和停留才可能被解释为价值路径的一部分 → 边界：首次价值必须由真实用户行为验证，团队自定义事件不等于用户已经获得结果。
  • 起点：增长漏斗 → 关系：提供行为分母与流失位置 → 终点：单位经济 → 为何：获客、激活、成交、交付、退款和复购共同决定每份收入需要承担多少渠道与履约成本 → 边界：跨平台归因不完整，同期变化不能自动归因于某条内容、标题或渠道。
  • 起点：任务契约 → 关系：界定承诺、验收与支持成本 → 终点：单位经济 → 为何：范围、人工复核、异常处理、退款和售后若未进入契约，表面毛利会系统性高估 → 边界：会议未提供可审计订单、账单或工时，具体金额必须由项目自己的台账核验。
  • 起点：单位经济 → 关系：约束扩量与可靠性投入 → 终点：可靠性 → 为何：稳定交付需要容量、监控、支持和恢复成本，持续亏损的路径无法只靠更多流量变可靠 → 边界：早期实验可以暂时不盈利，但应说明学习目标、预算上限和何时转入可持续口径。
  • 起点：可靠性 → 关系：保护交付、复访与复购 → 终点：增长漏斗 → 为何：服务中断、品质波动、供应失败和恢复缓慢会让前端触达在交付段流失 → 边界：留存或复购也可能来自折扣、关系维护或退出困难，不能全部归因于可靠性。
洞 07

控制环：停止条件把无证据扩张截断

停止条件贯穿内容提炼、技术实验、Agent 执行和商业经营。没有连续转写就停止主题复原；没有合法输入就停止训练、汇总或商业化；权限、预算和撤销不清就停止自动写入；端到端旅程不通就停止把 Demo 当产品；恢复未经演练就停止高风险变更；完整成本和交付责任不清就停止放量。停止不是永久否定，补齐材料后可以重新从证据治理节点进入，而不是把旧推断悄悄升级。

可以带走

  • 起点：证据缺口 → 关系：触发暂停与补证 → 终点：停止条件 → 为何：标题、零散短句、背景媒体或空白转写不足以支持主题、人物和行动归因 → 边界：停止只针对当前材料与当前结论，不证明原会议没有发生相关讨论。
  • 起点：数据权利不明 → 关系：阻断收集、训练、共享或商业化 → 终点：停止条件 → 为何：无法说明来源、用途和责任时，继续处理会把产品实验变成授权与声誉风险 → 边界：补齐授权后仍需最小化、权限、保留和安全审查。
  • 起点：恢复能力不足 → 关系：阻断高影响变更 → 终点：停止条件 → 为何：没有有效备份、回滚、撤销或人工接管时，一次误操作可能造成不可逆损失 → 边界：只存在备份文件不等于可恢复，必须验证完整性并演练关键旅程。
  • 起点：单位经济无法闭合 → 关系：限制固定成本与扩量 → 终点：停止条件 → 为何：获客、人工、失败、退款、供应和售后被漏算时，更多订单可能放大现金损失 → 边界：短期亏损实验是否继续取决于明确学习价值和预算，而不是本图给出统一阈值。
  • 起点：停止条件 → 关系：生成最小补证清单 → 终点：证据治理 → 为何：停止后的下一步应是取回完整材料、核对权利、补测真实旅程或演练恢复，而不是写得更流畅 → 边界：补证必须更新来源、状态和时间，不能覆盖旧结论或删除冲突历史。
洞 08

软件与 Agent 案例索引：局部成功如何在链路中失真

软件与 Agent 相关页面可以按节点回读。模型服务音频把优化对象从单一模型扩展到请求、缓存和编排，但具体厂商实现仍待核验；八月八日的开放现场把自动化写成需要数据权利、输入输出和失败处理的契约。八月十日多段开发记录依次暴露配置无版本、CI 通过但运行失败、长任务自报完成却缺少产物、权限域放错和支付后仍缺履约等断链。八月十一日的实施记录补充环境契约、模块所有权、数据质量、任务越界、上传恢复和资源预算；八月十三日则把规格版本、依赖图、真实任务评测、只读连接器与多语言验收连接起来。可迁移结论是每场案例照亮一个检查点，不能据此认定某个系统已经实施了整张图。

可以带走

  • 读模型与 Agent 页面时，先问真实任务、上下文预算、工具权限和最终产物，再问模型名称与调用数量。
  • 读部署页面时，把“已构建、已启动、可路由、可调用、质量达标、端到端通过、可恢复”作为不同状态保存。

洞 11

反例与断链：哪些箭头不能直接画

图谱最有价值的部分不是箭头数量，而是明确拒绝错误连线。页面标题不能直接连到会议事实；模型能回答不能直接连到工具可执行；工具可执行不能直接连到产物完整；CI 通过不能直接连到运行可用；访问或播放不能直接连到需求；付款不能直接连到利润；有权限不能直接连到有数据权利；存在备份不能直接连到可恢复；多个异常同期出现不能直接连到同一根因；四个 insufficient 页面不能直接连到其标题所暗示的主题。修复断链的方法是增加中间证据节点，而不是把箭头写得更肯定。

可以带走

  • 起点：标题或文件元数据 → 关系：不能直接证明 → 终点：会议主题与结论 → 为何：四个证据不足页面展示了标题存在但正文为空、稀疏或来源不明的情况 → 边界：补取完整材料并重新审查后，可以建立新的证据记录。
  • 起点：模型回答或代码生成 → 关系：不能直接证明 → 终点：端到端交付 → 为何：工具权限、依赖、运行、上传、质量和用户旅程仍可能断裂 → 边界：固定任务的完整轨迹、产物与独立验收可以逐步补上中间节点。
  • 起点：CI 绿灯或服务启动 → 关系：不能直接证明 → 终点：可靠产品 → 为何：运行配置、网关、身份、数据、依赖、弱网和恢复未必被构建检查覆盖 → 边界：若流水线确实包含代表性环境与全链路测试，应按其真实覆盖范围提高证据等级。
  • 起点：曝光、访问或注册 → 关系：不能直接证明 → 终点：需求与单位经济成立 → 为何：目标用户、首次价值、交付、退款、复购和完整成本仍未知 → 边界：高意愿行为可以增强需求证据，但仍需分母、时间窗和来源核对。
  • 起点：系统访问权限 → 关系：不能直接证明 → 终点：数据可训练、共享或商业化 → 为何：用途、主体、合同、个人同意、知识产权与保留条件可能分别受限 → 边界：具体权利应按材料、地区、合同和用途逐项确认。
  • 起点：备份文件存在 → 关系：不能直接证明 → 终点：恢复能力成立 → 为何：备份可能过期、不完整、与生产共故障或从未演练 → 边界：校验、隔离保留和恢复后端到端复验可补强证据。
  • 起点：同期故障或跨页共现 → 关系：不能直接证明 → 终点：单一根因或普遍因果 → 为何：网络、上游容量、配置、账号、内存和人工操作可能产生相似现象 → 边界：受控对照、链路日志和复现实验可以支持更窄的根因判断。
洞 12

导入个人知识库：节点、边、来源和状态分开保存

导入时不要把本页整段复制成一个永久真相。先建立十一张节点笔记，每张包含定义、适用问题、可观察证据、失败信号和关联页面；再把每条关系保存为独立边记录，字段至少包括起点、关系、终点、为何、边界、材料来源、材料状态、首次记录时间、最近更新时间、反证和待核验项。会议页以公开 slug 或可公开引用作为来源，不导入私人材料、敏感值或无法授权的附件。partial 与 insufficient 保留原状态，不因进入知识库而升级。遇到新材料时新增版本和关系候选；若新旧主张对象、时间和条件不同，先拆作用域，若相同作用域仍不相容，则建立冲突记录并并列保留。

可以带走

  • 节点笔记保存概念定义，边记录保存方向和条件，来源笔记保存材料本身；三者分开可避免一次改写覆盖原证据。
  • 每条主张同时保留来源、状态、更新时间和适用范围；没有这些字段的流畅总结只能作为待整理材料。
  • 用双向链接把节点接回会议单页，也允许从单页查看它支持、反驳或只提出了哪些节点与关系。
  • 对同一主张采用追加版本，不静默覆盖；过期不等于错误，需保留当时条件和被替代原因。
  • insufficient 材料只挂到证据缺口、补证任务和停止条件，不挂到主题结论节点。
  • 导入完成后抽样从节点沿边回到公开页面，检查是否仍能看到状态、局限和待核验项。
洞 13

让 Agent 增量挂图：追加、比对、冲突，不补写

Agent 每次只处理用户新交付的一批材料，并先生成材料登记：公开名称或安全引用、来源类型、材料状态、覆盖时间、最近更新时间、允许用途和敏感边界。随后把文本拆成原子主张，分别标记“材料明确陈述、从材料提炼的方法、Agent 推断、待外部核验或证据不足”，再尝试连接现有十一节点。新增边必须使用“起点—关系—终点—为何—边界”五段格式并引用材料登记；旧边不覆盖，只追加支持、反证、范围修正或过期候选。冲突检测应比较同一对象、同一指标、同一时间窗和同一条件下的结论，输出冲突双方、来源状态、更新时间、差异条件和最小解决证据。若只有标题、摘要、来源不明片段或敏感未授权内容，Agent 应挂到补证队列并停止主题推断。

可以带走

  • 增量处理只提交新增节点、边、来源、状态变化和冲突，不重新生成整张图来掩盖历史差异。
  • 来源状态与主张状态分开：一个 partial 页面可以支持窄方法结论，但不能因此被升级为完整会议记录。
  • 更新时间表示记录何时被审查或修订，不表示事实何时发生；两种时间必须分别解释。
  • 检测冲突前先对齐对象、口径、时间窗、环境和适用人群，避免把条件不同误报为矛盾。
  • 真正冲突时并列保存双方并降低自动决策权限，直到用户提供更强材料或完成受控验证。
  • Agent 不得补造缺失数字、发言、人物归属、实现结果、平台规则或因果；无法连接时输出“证据不足”也是合格结果。
洞 14

一条可执行的遍历顺序：用下一条关键证据决定去向

面对一个新项目，不必把十一节点一次填满。先写出目标用户、触发时刻和真实任务，建立主张与来源账本；确认数据权利后，再用最小权限写任务契约。用一个代表性旅程做端到端验收，记录失败样本，再补可靠性、恢复和人工升级。产品能稳定交付后，把触达追到首次价值、付款、交付与复购，并核算风险调整后的单位经济。每轮只问“哪条新证据会改变下一笔投入”，同时预写停止条件。任何节点证据不足，都回到相邻前置节点补证，而不是让 Agent 增加功能、文字或箭头。

可以带走

  • 第一轮最小产物是任务卡、来源账本、权利清单、权限边界和一个可观察完成信号。
  • 第二轮最小产物是端到端轨迹、失败分类、恢复演练与具名人工升级点。
  • 第三轮最小产物是有分母的漏斗、完整成本、交付记录、退款或复访原因和决策日期。
  • 每轮只允许“继续、缩小、转向、停止、证据不足”五种状态，并引用新材料说明变化。
  • 图谱的完成标准不是节点全亮，而是关键决定能沿来源、状态、边界和更新时间回溯。

道 · 法 · 术 · 器 · 势

  1. 道01

    知识图谱的价值不在把会议说得更完整，而在让每个决定受证据、权利、责任与可逆性约束；AI 可以扩展检索和连接，人仍对来源、冲突与行动后果负责。

  2. 法02

    以节点统一概念，以有向边声明关系和边界，以来源与状态约束主张强度，以真实任务和端到端验收取得证据，再用恢复、单位经济和停止条件闭环。

  3. 术03

    把材料拆成原子主张；为每条边记录起点、关系、终点、为何和边界；对齐对象与时间窗后检测冲突；以追加版本保存支持、反证、过期与补证任务。

  4. 器04

    使用节点笔记、边记录、来源索引、状态字段、更新时间、反证队列、权限矩阵、任务契约、端到端轨迹、恢复演练、增长漏斗和单位经济表承载图谱。

  5. 势05

    生成式工具让原型、内容和连接器更容易出现，竞争瓶颈因此向真实任务、数据权利、可靠交付、恢复能力、信任与完整经营结果迁移；材料变化越快，越需要增量更新而非静态定论。

继续追问

  3. 它连接十一节点中的哪两个节点，方向、为何与适用边界分别是什么？
  4. 相关关系只是跨页共现，还是已有真实任务、对照、日志、行为或经营记录支持？

  6. 若确有冲突，双方来源状态、更新时间和最小解决证据分别是什么？
  7. 数据来源、用途、保留、共享与商业化权利是否已被逐项说明？
  8. Agent 当前拥有的读取、写入、付费、发布、删除和撤销权限是否小于等于任务需要？
  9. 端到端完成、可靠性与恢复分别有哪些证据，哪一层仍只凭局部成功推断？
  10. 增长事件是否能追到首次价值、交付和复购，单位经济是否包含人工、失败、退款、售后与风险？
  11. 什么条件应立即停止总结、自动执行、发布、收费或继续投入？
  12. 本次更新后，哪些旧结论应保留、降级、标为过期或进入补证队列？

证据治理节点

为每条主张保存安全来源、材料状态、主张状态、适用范围、首次记录时间、最近更新时间、反证与缺口；状态变化采用追加记录，不覆盖历史。

真实任务节点

用目标用户、触发时刻、当前替代、真实输入、关键动作和可观察结果定义任务；功能想法、标题热词和会议频次都不能替代用户行为。

任务契约节点

任务契约至少写输入、版本、范围、禁止项、权限、产物、质量、预算、负责人、检查点、失败处理和停止条件；模糊动词不能作为完成定义。

端到端验收节点

沿真实用户旅程检查身份、输入、处理、依赖、输出、支付或交付、异常与交接；构建成功、服务启动或 Agent 自报完成只属于局部证据。

可靠性节点

在代表性负载、弱网、依赖故障、权限差异和长任务下检查质量、时延、错误、资源、可观测性与降级；单次成功不代表持续交付。
