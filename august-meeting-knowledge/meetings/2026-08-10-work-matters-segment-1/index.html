03

可迁移知识

知 01

先审计证据覆盖，再决定总结粒度

为什么重要
录音很长但有效文字很少时，文件标题、关键词和常识会诱导整理者拼出一场并不存在于证据中的完整会议。
怎么使用
记录总时长、首末有效发言、长空档、连续工作对话数量和背景内容比例；只保留有上下文与真实时间锚点共同支持的主题，其余登记为覆盖缺口。
适用边界
本页只能判断当前导出的转写覆盖稀疏，不能据此断言原始录音缺失区间没有声音或没有工作活动。
知 02

主观体验必须升级为任务级基准

为什么重要
同一模型在写作、编码、检索和工具调用上的表现可能不同；一句“更聪明”或“更笨”既不可复现，也不足以支持采购、推荐或对外分享。
怎么使用
固定真实任务集、输入与期望结果，记录准确模型名和版本、配置、运行日期、成功标准、时延、成本和失败案例；对候选模型使用相同条件并保留人工盲评。
适用边界
会议没有提供任何基准结果；本文给出的评测方法是通用补证框架，不证明片段中的个人判断正确或错误。
知 03

外部经验分享要附上证据等级

为什么重要
有偿访谈容易把一次短暂体验包装成稳定能力判断，也可能让听众误以为讲述者验证过未实际测试的功能。
怎么使用
在访谈前列出亲自操作过的任务、可展示记录、他人转述和未知项；回答时说明测试时间与环境，对超出经验范围的问题明确保留。
适用边界
转写没有访谈提纲、用途、参与者身份或最终回答，不能判断该访谈是否发生，也不能推断任何利益关系或合规结论。
知 04

复用检索从用途与约束开始

为什么重要
“能接多个模型的项目”可能指界面、开发库、代理网关或完整应用；不先澄清用途，搜到的热门项目也可能无法运行、不可商用或维护停滞。
怎么使用
先写明目标用户、接入形态、所需模型类型、运行环境、网络与数据边界，再比较许可证、更新活跃度、扩展方式、鉴权设计、部署难度、测试和退出成本。
适用边界
会议只要求去既有资料中搜索，没有确认任何候选项目、技术架构或选型决定；所有候选必须重新查阅其当前官方资料。
知 05

流量问题要拆成可观测路径

为什么重要
仅问“流量从哪里来”会混合自然发现、平台推荐、外部投放、社交分享和已有用户回流，也无法区分曝光、访问、激活和留存。
怎么使用
为目标场景画出入口到关键行为的路径，逐步定义事件、来源标记、转化窗口和成功指标；分别核对平台公开能力、用户授权、数据最小化和归因盲区。
适用边界
会议没有提供真实后台数据、平台规则或用户研究，本文不声称任何游戏与小程序已经互通，也不判断具体渠道效果。
知 06

Agent 数量服从可执行任务图

为什么重要
大量 Agent 若共享同一模糊问题，会重复搜索、互相覆盖并放大未经核验的说法；并行数量本身不代表覆盖度或质量。
怎么使用
先把研究拆为互斥问题，为每项指定输入来源、输出结构、文件所有权、验收标准和停止条件；只并行无前置依赖的任务，最后由主任务去重、核源并处理冲突。
适用边界
会议只留下数量要求，没有证据表明 Agent 已启动、采用了何种分工、完成了多少任务或产生了可验收成果。
知 07

孤立的交易与配置残句不应进入公开知识结论

为什么重要
付款、下单、访问配置和第三方相关词语一旦脱离上下文，既可能暴露隐私，也很容易被误写成债务、授权或技术事故。
怎么使用
对这类片段仅登记存在覆盖缺口；需要处理时回到受控私域核对合同、工作记录、系统日志和授权链，不在公开页面保留人物、金额或访问细节。
适用边界
本原则是本页的隐私与证据处理方法，不对片段涉及的任何个人、组织、交易或系统状态作判断。
04

道 · 法 · 术 · 器 · 势

  1. 道01

    可靠研究的核心不是把稀疏对话讲得完整，而是让每个判断都能回到证据；模型、项目、流量和 Agent 规模都必须服务于可验证的问题。

  2. 法02

    采用“覆盖审计—问题澄清—证据分级—小规模验证—依赖拆分—并行检索—交叉核验”的路径，缺少输入、结果或决定时保持未知。

  3. 术03

    用固定任务集比较模型，用筛选矩阵检索复用项目，用入口与事件图拆流量，用任务依赖图和统一输出 schema 管理 Agent。

  4. 器04

    带时间戳的完整来源、模型评测表、候选项目清单、许可证与维护记录、流量事件字典、来源台账、Agent 任务卡和冲突复核表。

  5. 势05

    模型选择增多、应用生态交叉和 Agent 并行门槛下降，会让检索更快，也会同步放大版本混淆、重复研究和未经核验的判断；本场不足以证明更广泛市场趋势。

覆盖审计卡

先记录总时长、有效转写区间、长空档和生活内容比例；标题与关键词不补证，稀疏来源只做片段级提炼。

模型基准卡

固定任务、输入和成功标准，核准名称与版本，同时记录质量、时延、成本和失败样本；个人印象不等于排名。

复用筛选卡

先确认项目形态和目标环境，再看支持能力、许可证、维护状态、数据路径、部署验证与退出成本；热门不等于适用。

流量路径卡

把模糊流量问题拆为入口、关键事件、来源标记、转化窗口、归因盲区和数据边界，逐步绑定公开证据。

Agent 并行卡

并行规模由无阻塞任务集合决定；每项必须有唯一问题、文件所有权、来源、输出 schema、验收和停止条件。

公开边界卡

人物、金额、交易、访问配置和第三方关系的孤立残句不进入公开结论；确需处理时只在私域依据正式记录核验。
