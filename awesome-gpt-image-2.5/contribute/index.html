参与贡献

无需编程或注册本站：在 GitHub Issue 中提交新案例、外部推荐或复现记录。所有内容都会先核对来源、运行信息和许可，再决定是否收录。

选择一个入口

点击下面的入口会打开项目 GitHub Issue 表单。你不需要注册本站账号；GitHub 可能会要求登录以提交 Issue。按表单提示填写即可，不需要写代码或创建 Pull Request。

提交新案例（提示词、结果图和来源） →

推荐外部案例或教程（只需公开原始链接） →

提交复现结果（成功或失败都可以） →

图片、作者与许可

在 Issue 表单的“结果图片与参考素材”框中，可以直接拖入或粘贴图片。请同时写明图片作者、原始来源链接，以及允许公开展示、下载或再利用的范围；如果图片来自第三方，请保留其原作者和原许可，不要把上传者写成作者。

请只上传你有权提交的图片和素材。不要上传私人会话截图、令牌、身份证件、私密文件或包含个人隐私的内容。

  • 原创作品：分别说明提示词作者和结果图作者，并给出首次公开发布链接（如有）。
  • 引用或改编：写出原作者、原始链接、改动内容和原许可；投稿者署名与原作者署名分开记录。
  • 不确定许可：先给出公开来源和当前能确认的线索，维护者会在审核时核对。

把复刻记录写清楚

复现结果是你在自己的入口和日期运行得到的记录，不会自动变成上游作品。请在复现表单中写明案例编号或链接、实际提示词改动、模型与入口、日期、必要输入，以及结果图片。成功和失败都值得提交。

  • 本人作品：标明这是你本人编写或生成的版本，并说明是否使用了自己的参考图。
  • 引用或改编：保留原作者和上游结果的链接；把你的修改、运行结果和上游作品分开描述。
  • 缺少输入图或运行证据时，写成“独立尝试”或“待核对”，不要把相似画面写成已复刻。

先审查，再收录

提交 Issue 后不会自动发布到图鉴。维护者会先检查公开来源、作者与许可说明、图片可用性、运行条件和复现表述；必要时会在 Issue 中请求补充或更正。只有完成审核并满足收录条件的内容，才会进入网站和案例目录。

  • 推荐链接不等于转载授权，也不保证会进入已验证案例目录。
  • 维护者可能补充图片描述或调整分类，但会保留可核对的作者和来源记录。
  • 如果内容涉及权属错误、作者更正或撤下，请使用专门的权利请求表单。
