# 项目与会议目录

[在线目录](https://siuserxiaowei.github.io/catalog/) · [会议主题](https://siuserxiaowei.github.io/catalog/#view=meetings) · [项目说明](项目说明.md)

目录解决三个问题：项目做什么、从哪里进入、当前能确认什么状态。会议包含独立仓库与合集里的条目；同一场会议可以有分段和不同整理版本。

## 维护

`catalog.json` 是经过审阅的公开目录数据。修改后运行：

```bash
python3 catalog/build.py
python3 -m http.server 8000
```

打开 `http://localhost:8000/catalog/` 检查搜索、主题筛选、状态筛选、分页与移动端。生成脚本更新浏览器数据、CSV 和逐项目说明，不访问 GitHub，也不会自动发布。

新增仓库时，先判断能否进入已有项目；需要独立安装、部署或协作的项目再单独建仓库，并同时增加目录条目。更新用途或入口时同步修改对应字段。

## 内容约定

- 每个项目必须有中文用途、真实入口、可核对状态、来源链接和分类。
- 会议标题优先采用原资料的主题；时间戳标题可用原章节主题替换，但须保留 `originalTitle`，并记录 `sourceBasis`。
- `archiveDate` 在会议记录里表示原材料标注的日期；不要用仓库上传日期冒充录音日期。`updated` 保存核对时的最近推送日期。
- “网页可访问”只代表核对时入口响应正常，不代表功能验收。缺少实测时写明；不能根据推送时间擅自判断维护意愿。
- 不在公开目录中加入私有项目、私有源码关系、内部资源标识、访问凭据或明确要求不外传的资料。
- 原仓库和原文保持可回查；索引整理不等于已迁移内容，也不授权删除或归档原仓库。

## 本次覆盖与限制

2026-09-12 核对账号全部仓库的元信息、默认分支根目录和可用 README。公开目录对照了原页面标题、47 个日期编号仓库的摘要与录音日期，以及会议合集现有结构化索引。部分主题取自首个实质章节，不代表已经逐句校订全部录音。

现有网站入口完成 HTTP 检查；集合内的深层链接优先对照仓库文件路径。完整应用功能未逐个运行测试。
