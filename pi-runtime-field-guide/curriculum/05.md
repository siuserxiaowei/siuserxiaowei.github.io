# 05 · 流式与取消：看到片段，不等于允许执行

版本：Pi v1.5.0 · 核验：2026-11-03T21:19:39+08:00 · 固定源码：`f9a26365568127461c47a07a37dcb42c140a3ac5`

将流式展示、最终响应、工具参数验证和 AbortSignal 分开，理解 v1.5.0 如何避免执行输出截断的工具调用。

## 先想三个问题

1. toolcall_delta 中看起来完整的参数，为什么仍不能马上执行？
2. stopReason 为 length 时，即使 Schema 验证能通过，工具能否运行？
3. 取消请求能保证什么，又不能撤销哪些已经发生的外部行为？

## 流事件用于观察，最终消息决定下一步

pi-ai 把一次回答表示为 start、文本或 thinking 增量、工具参数增量，最后以 done 或 error 收口。AssistantMessageEventStream.result() 给出最终 AssistantMessage。Agent 把流映射为 message_start / update / end，再进入工具阶段。

流中工具参数可以增量解析，用于 UI 展示和减少重复解析开销，但片段不是执行许可。Agent 先结算最终响应，等待 assistant message_end 的订阅屏障，再预检工具；这样审计或宿主不会在工具已经动手后才收到完整请求。

- 部分内容可展示；停止原因、完整工具参数和验证结果决定能否执行。

## 输出截断时拒绝本条回答的全部调用

如果最终 stopReason 是 length，模型输出可能在任何工具参数中间被截断。修复型 JSON 解析器有时能得到看似合法的对象，甚至能通过 Schema；这仍不证明模型本来就打算执行这个值。

v1.5.0 的 loop 对该 assistant message 中所有工具调用生成失败结果，不执行工具体，然后让模型按正常工具/队列规则继续。普通参数校验失败、未知工具和工具体异常也应变成明确错误结果，不要把半截参数当作成功输入继续写入。

- “可解析”不等于“完整”；Schema 约束也不能恢复模型尚未生成的意图。

## 取消是协作终止，不是事务回滚

models.stream() 接收 AbortSignal，Agent.abort() 会触发当前运行的取消信号；自定义 StreamFn、工具及外部程序必须配合响应。最终 aborted 消息可以保留部分内容与用量，不能把用户按下停止键解释为本次请求从未发生。

模型请求已经收费、文件已经写入或消息已经发送时，取消不会自动撤销副作用。工具还要有清理、超时、幂等或补偿设计。CLI 保存历史与 Durable 的恢复策略也不是继续同一条供应商流，不能承诺从断开的 token 原位恢复。


## 实验：截断调用不执行，取消保留明确终态

用 Faux 构造能通过类型检查但输出被截断的调用，再观察协作取消。

运行条件：离线（需预先安装固定版本依赖）

1. 在实验目录保存为 stream-lab.mjs，依赖版本与第 4 章相同。
2. 运行 node stream-lab.mjs；echo 只修改内存计数，不写文件或发网络请求。
3. 先检查截断分支的零执行计数，再检查慢速文本流被 abort 后的终态。

```javascript
import assert from "node:assert/strict";
import { Agent } from "@earendil-works/pi-agent-core";
import { createModels, fauxProvider, fauxAssistantMessage, fauxToolCall } from "@earendil-works/pi-ai";
const models = createModels();
const faux = fauxProvider();
models.setProvider(faux.provider);
let executed = 0;
const echo = {
  name: "echo", label: "Echo", description: "Count executions",
  parameters: { type: "object", properties: { value: { type: "string" } }, required: ["value"] },
  execute: async () => { executed++; return { content: [{ type: "text", text: "ok" }], details: {} }; },
};
faux.setResponses([
  fauxAssistantMessage([fauxToolCall("echo", { value: "hel" })], { stopReason: "length" }),
  fauxAssistantMessage("recovered"),
]);
const agent = new Agent({ initialState: { model: faux.getModel(), tools: [echo] }, streamFn: models.streamSimple.bind(models) });
await agent.prompt("test truncation");
const errors = agent.state.messages.filter(x => x.role === "toolResult" && x.isError);
assert.equal(executed, 0);
assert.equal(errors.length, 1);
const slow = fauxProvider({ tokensPerSecond: 20 });
models.setProvider(slow.provider);
slow.setResponses([fauxAssistantMessage("a deliberately long offline response for cancellation")]);
const cancelled = new Agent({ initialState: { model: slow.getModel() }, streamFn: models.streamSimple.bind(models) });
cancelled.subscribe(event => {
  if (event.type === "message_update" && event.assistantMessageEvent.type === "text_delta") cancelled.abort();
});
await cancelled.prompt("test abort");
const last = cancelled.state.messages.at(-1);
assert.equal(last.stopReason, "aborted");
console.log({ executed, toolErrors: errors.length, cancelled: last.stopReason });
```

### 预期结果

- executed 为 0，toolErrors 为 1；字符串 hel 虽符合 Schema，也没有被执行。
- 第二次运行的最终 stopReason 为 aborted，脚本断言通过。

验收：观察零副作用计数和明确的 aborted 终态；该测试不证明任意第三方工具或供应商都能及时响应取消。

依赖准备后不调用真实 API。Faux 只控制事件，不代表网络断流、计费或进程恢复测试。

## 容易混淆的地方

- 在 toolcall_delta 到达时提前运行工具。
- 仅因 JSON 可修复或 Schema 通过，就忽略 length 停止原因。
- 把 abort、UI 不再输出和外部副作用回滚当成同一结果。

## 版本变化

length 响应中的全部工具调用仍转为失败结果；增量解析不代表可提前执行。
