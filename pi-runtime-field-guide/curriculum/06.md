# 06 · 工具管道：参数验证、并发与 MCP / Codemode

版本：Pi v1.5.0 · 核验：2026-11-03T21:19:39+08:00 · 固定源码：`f9a26365568127461c47a07a37dcb42c140a3ac5`

沿 v1.5.0 的真实工具管道，从 JSON Schema、Hook 和执行顺序，理解 MCP 与脚本调用如何进入同一套工具契约。

## 先想三个问题

1. 参数验证通过，为什么仍不代表允许执行工具？
2. 并行工具的完成事件顺序，为什么可以不同于持久化结果顺序？
3. MCP 和 Codemode 分别增加什么能力，又不能替代什么安全控制？

## 先把工具定义与执行权限分开

工具不仅是一个函数，还包括名称、说明、JSON Schema 参数、执行函数和可选的参数准备逻辑。v1.5.0 使用 pi-schema 处理验证与类型推导；Schema 可以是普通 JSON 对象，不再要求依赖 TypeBox。TypeBox 的常见 JSON Schema 类型仍有兼容路径，但 JavaScript 专属类型、refinement 或 codec 不能当成通用 Schema 使用。

pi-schema 的 check 判断值是否合法，开启 coerce 后才提供转换与 parse；转换不会直接改写调用者的原对象。默认值只是注释，不会自动补入参数。参数合法只解决形状和类型问题，业务权限、路径范围、额度和副作用仍要由工具与宿主决定。

- 把危险参数约束写进 Schema，也在工具执行边界检查真实资源。
- 不要把“模型能看见这个工具”理解成“这个调用已经获得授权”。

## 一次调用经过哪些阶段

管道依次查找工具，调用可选 prepareArguments，再验证参数、运行 beforeToolCall、执行工具并收集进度，最后运行 afterToolCall。未知工具、无效参数、阻止执行以及抛出的异常都会形成 isError 结果，交给上层处理。验证失败不会进入前置 Hook；被前置 Hook 阻止的调用也不会进入执行和后置 Hook。

runToolCall 提供同样的准备、验证和 Hook 语义，适合工具内部再调用工具。它自己不发送事件，也不追加会话消息。Codemode 等组合工具可以沿这个入口调用底层工具，保留宿主的拦截策略，而不是绕开管道直接调用函数。

- afterToolCall 可以改写结果，但不应掩盖已经发生的外部副作用。
- durationMs 度量工具 execute 的耗时，不包含 Hook 和队列等待。

## 并发不等于结果乱序

默认 parallel 模式按 assistant 中的调用顺序依次预检，再并发运行获准工具。tool_execution_end 按实际完成顺序发出，但最终 toolResult 消息和 turn_end.toolResults 按 assistant 的原始顺序提交。因此 UI 看到 B 先完成，并不表示历史里 B 应排在 A 前面。

任一工具声明 executionMode 为 sequential 时，整个批次顺序执行。批次中每个最终结果都设置 terminate:true，才会跳过自动后续模型请求；混合批次不会因其中一个工具要求停止就全部结束。


## MCP 提供工具，Codemode 组织调用

原生 MCP 支持 stdio 和 streamable HTTP，不支持旧 SSE；用户配置与经过信任确认的项目配置共同决定连接和暴露方式。pi mcp list 会实际连接启用的服务器，不只是读取配置。Codemode 不在基础默认工具列表中，可用 pi --tools +codemode 追加；MCP 也会按 codemode 或 deferred 暴露需求自动启用 Codemode 或 tool_search。

Codemode 的输入是 JavaScript 源码，运行于没有 Node、文件系统、网络与计时器 API 的 QuickJS 环境。脚本通过工具调用外部资源，可并发筛选结果，只把必要输出交给模型。但被调用工具会真实执行；脚本后续报错不会撤销此前的写入，QuickJS 也不会把 bash 自动变成安全沙箱。


## 实验：离线验证合法、无效、被拦截与不存在的工具

调用真实 runToolCall，证明验证和 Hook 的先后边界；本实验不测试模型是否会选对工具。

运行条件：离线（需预先安装固定版本依赖）

1. 准备 Node.js 22.19 或更新版本，以及临时 Node 项目中的 @earendil-works/pi-agent-core@1.5.0 和 @earendil-works/pi-schema@1.5.0。首次安装依赖需要联网，实验执行不需要账号。
2. 将下面代码保存为 tool-pipeline.mjs，在该临时项目目录执行 node tool-pipeline.mjs。
3. 查看结果与日志，确认只有合法且未被拦截的调用进入 execute。

```javascript
import assert from 'node:assert/strict';
import { runToolCall } from '@earendil-works/pi-agent-core';
import { obj, str } from '@earendil-works/pi-schema';
let executions = 0;
const hooks = [];
const tool = {
  name: 'echo', label: 'Echo', description: 'Return a string',
  parameters: obj({ value: str() }),
  async execute(_id, args) {
    executions++;
    return { content: [{ type: 'text', text: args.value }], details: {} };
  },
};
const usage = { input: 0, output: 0, cacheRead: 0, cacheWrite: 0,
  totalTokens: 0, cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0, total: 0 } };
const options = {
  tools: [tool], context: { messages: [] },
  assistantMessage: { role: 'assistant', content: [], api: 'faux',
    provider: 'faux', model: 'faux-1', usage, stopReason: 'stop', timestamp: 0 },
  beforeToolCall: async ({ toolCall, args }) => {
    hooks.push(`before:${toolCall.id}`);
    if (args.value === 'blocked') return { block: true, reason: 'blocked by lab' };
  },
  afterToolCall: async ({ toolCall }) => { hooks.push(`after:${toolCall.id}`); },
};
const results = [];
for (const [id, name, args] of [
  ['ok', 'echo', { value: 'ok' }],
  ['invalid', 'echo', { value: { nested: true } }],
  ['blocked', 'echo', { value: 'blocked' }],
  ['missing', 'missing', {}],
]) results.push(await runToolCall({ type: 'toolCall', id, name, arguments: args }, options));
assert.deepEqual(results.map(x => x.isError), [false, true, true, true]);
assert.equal(executions, 1);
assert.deepEqual(hooks, ['before:ok', 'after:ok', 'before:blocked']);
console.log(JSON.stringify({ errors: results.map(x => x.isError), executions, hooks }));

```

### 预期结果

- isError 序列为 false、true、true、true；所有调用都返回结果对象，工具失败不会让本探针直接抛出未处理异常。
- execute 只运行一次；invalid 和 missing 不进入 Hook，blocked 进入前置 Hook 后停止。

验收：所有 assert 通过且进程退出码为 0；修改为无效参数后 execute 计数仍不增加。

离线指依赖已就绪后的执行阶段。这里只测 runToolCall，不会发 provider 请求，不会启动 MCP，也不产生 Agent 会话事件；并发和 MCP 连通性需要另做集成实验。

## 容易混淆的地方

- 把 Schema 验证当作权限检查，或以为 default 会自动补值。
- 按照 tool_execution_end 的到达顺序重排持久化工具结果。
- 把 Codemode 的 QuickJS 隔离等同于所有被调用工具的操作系统隔离。

## 版本变化

用当前 pi-schema、默认并行执行、runToolCall 和原生 MCP/Codemode 重新解释工具契约；旧 TypeBox 专属假设和第三方 MCP 限制不再作为本章前提。
