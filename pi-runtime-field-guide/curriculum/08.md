# 08 · 事件与集成：什么时候真的结束了

版本：Pi v1.5.0 · 核验：2026-11-03T21:19:39+08:00 · 固定源码：`f9a26365568127461c47a07a37dcb42c140a3ac5`

用事件边界区分请求被接受、一次低层运行结束和会话完全静止，并选择 SDK 或 JSONL RPC 接入。

## 先想三个问题

1. RPC 的 prompt success:true，是否代表任务已经完成？
2. agent_end 与 AgentSession 的 agent_settled 有什么区别？
3. 为什么工具完成事件、会话记录和遥测不能互相替代？

## 先读懂一次低层运行的时间线

一次正常 Agent 运行从 agent_start、turn_start 开始，依次产生消息开始、流式更新、消息结束；若有工具调用，再经过工具执行事件与结果消息，最后发出 turn_end。工具结果需要后续判断时会进入下一轮，直到 agent_end 收口。message_update 是 assistant 的增量事件，不能当成已经完成的一条消息。

Agent.subscribe 的监听器按注册顺序被等待。agent_end 表示不会再发出该低层运行的事件，但它的异步监听器仍可能尚未结束；prompt 和 waitForIdle 要等待这些工作结算。把“收到最后一个事件”和“调用方的 Promise 已完成”当成同一瞬间，会制造资源释放和 UI 状态竞态。


## 会话结束比一轮结束更高一层

Coding Agent 的 AgentSession 还负责自动重试、溢出恢复、压缩和输入队列。因此某次 agent_end 后，仍可能启动新的运行。外部客户端需要确认 Pi 不会自动继续时，应等待会话层的 agent_settled，而不是在第一个 agent_end 就展示最终交付。

RPC prompt 的成功响应只是输入已经开始、排队或被扩展处理；handled 表示没有为这条输入开启运行，不能机械等待一个不会出现的 agent_settled。订阅应先于发送 prompt，避免快任务在订阅建立前就结束。

- 显示“已受理”“运行中”“等待复核”和“已静止”等不同业务状态。
- 完成事件不自动代表用户的验收条件已经满足。

## SDK 与 RPC 是两种边界

Node.js 或 Bun 应用可用 SDK 在进程内直接访问 AgentSession、会话和工具，生命周期结束时 dispose。其他语言、IDE 或需要进程隔离的宿主可使用 pi --mode rpc，以 stdin/stdout 的 JSONL 命令、响应和事件通信；TypeScript 子进程集成也可使用官方 RpcClient。

每条协议记录必须是一个完整 JSON 对象，以 LF 结束。并发命令按唯一 id 关联响应，不能依赖返回顺序；U+2028 和 U+2029 可以出现在 JSON 字符串内，不能把它们当协议换行。持续读取 stdout 并处理背压；诊断在 stderr，进程退出与超时必须由客户端处理。


## 进度、持久事实和遥测各有用途

并行工具的完成事件按实际结束先后到达，而持久化结果仍按模型原调用顺序。界面可以先显示已完成的工具，历史重建却要遵守持久记录。durationMs 只表示 execute 的耗时，不包含 Hook、队列和整个业务请求。

pi-telemetry 提供与供应商无关的诊断契约和适配器边界。Trace 不是持久应用状态，carrier 也不是授权凭证；更换适配器不能改变会话的业务事实。默认不要把完整提示词、文件、工具输出和凭证写进观测属性；记录可用的低基数操作信息即可。


## 实验：无 prompt 的 RPC 协议探针

在隔离配置中向真实 Pi CLI 查询状态、统计与消息，验证 JSONL framing 和按 id 匹配响应。

运行条件：已安装 Pi CLI

1. 准备已安装的 @earendil-works/pi-coding-agent@1.5.0 与 Node.js 22.19+；将代码保存为 rpc-inspect.mjs，放在能解析该包的临时 Node 项目中。
2. 执行 node rpc-inspect.mjs。脚本使用临时工作目录和临时 PI_CODING_AGENT_DIR，禁用发现的扩展、技能、模板、主题和上下文文件。
3. 代码不发送 prompt，不发起模型推理；读取完三条命令响应后关闭 stdin。

```javascript
import assert from 'node:assert/strict';
import { spawn } from 'node:child_process';
import { once } from 'node:events';
import { mkdtemp } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';
const cli = join(dirname(fileURLToPath(import.meta.resolve('@earendil-works/pi-coding-agent'))), 'cli.js');
const work = await mkdtemp(join(tmpdir(), 'pi-rpc-inspect-'));
const child = spawn(process.execPath, [cli, '--mode', 'rpc', '--no-session',
  '--no-extensions', '--no-skills', '--no-prompt-templates', '--no-themes', '--no-context-files'],
  { cwd: work, env: { PATH: process.env.PATH ?? '', TERM: 'dumb', NO_COLOR: '1',
      PI_CODING_AGENT_DIR: join(work, 'agent') },
    stdio: ['pipe', 'pipe', 'inherit'] });
let buffer = '';
const waiting = new Map();
child.stdout.setEncoding('utf8');
child.stdout.on('data', chunk => {
  buffer += chunk;
  let end;
  while ((end = buffer.indexOf('\n')) >= 0) {
    const line = buffer.slice(0, end).replace(/\r$/, '');
    buffer = buffer.slice(end + 1);
    if (!line) continue;
    const record = JSON.parse(line);
    if (record.type === 'response' && waiting.has(record.id)) {
      const { resolve, timer } = waiting.get(record.id);
      clearTimeout(timer); waiting.delete(record.id); resolve(record);
    }
  }
});
function ask(type) {
  const id = `lab-${type}`;
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => { waiting.delete(id); reject(new Error(`Timeout: ${id}`)); }, 30000);
    waiting.set(id, { resolve, timer });
    child.stdin.write(JSON.stringify({ id, type }) + '\n');
  });
}
try {
  for (const type of ['get_state', 'get_session_stats', 'get_messages']) {
    const response = await ask(type);
    assert.equal(response.id, `lab-${type}`);
    assert.equal(response.command, type);
    assert.equal(response.success, true, JSON.stringify(response));
    console.log(JSON.stringify({ id: response.id, command: type, success: response.success }));
  }
  const exited = once(child, 'exit');
  child.stdin.end();
  const [status] = await exited;
  assert.equal(status, 0);
} finally {
  if (child.exitCode === null) child.kill();
}

```

### 预期结果

- 收到三条 id 与 command 对应且 success:true 的 response；不要求按随机启动事件的位置取第 N 行。
- 没有发送 prompt，因此本实验不验证模型输出、工具调用和 agent_settled 的整段生命周期。

验收：三条查询断言通过且 Pi 正常退出；手工把某条命令改为不存在的 type，应得到失败响应而不是把它解释为任务成功。

这是无模型推理的协议检查，需要已安装的 CLI 包；子进程只继承 PATH，不继承模型 API 凭证环境变量，使用临时配置目录，不读取或覆盖用户真实 Pi 配置。完整事件实验需额外 provider 凭证，本节不声称已完成该测评。

## 容易混淆的地方

- 把 prompt 的 success:true 或第一个 agent_end 当作业务任务完成。
- 用按所有 Unicode 换行切割的通用 reader 解析 JSONL。
- 把遥测事件当作恢复所需的持久状态，或把 trace id 当作授权凭证。

## 版本变化

用当前 RPC 文档的受理语义和 agent_settled 边界重写，不再用旧 agent_end 事件推断整个会话已经结束。
