# 10 · 压缩与分支摘要：重建工作现场，不删除历史

版本：Pi v1.5.0 · 核验：2026-11-03T21:19:39+08:00 · 固定源码：`f9a26365568127461c47a07a37dcb42c140a3ac5`

学习当前压缩的触发、合法切点、系统检查点与摘要累计机制，再把它和离开分支时的信息交接分开。

## 先想三个问题

1. reserveTokens 与摘要模型的最大输出长度，为什么不是同一个参数？
2. 压缩为何不能从一条 toolResult 开始保留上下文？
3. compaction 的 firstKeptEntryId 与 branch_summary 的 fromId 分别回答什么问题？

## 阈值决定何时压缩，不决定摘要写多长

默认条件仍是 contextTokens 大于 contextWindow 减 reserveTokens，默认 reserveTokens 为 16384，可由用户、项目和按模型设置调整。它决定何时开始压缩，不是摘要输出上限；当前摘要请求按模型输出能力和剩余窗口共同约束，不能把 reserveTokens 直接当 maxTokens。

会话会在新用户输入前检查，也会在工具结果追加后、下一响应准备阶段检查规范投影。若本批工具已终止运行且没有排队输入要求继续，就跳过该轮间检查。手工 /compact 可以附带说明；溢出和部分 length 情况另外走一次恢复尝试。


## 切点必须留下完整的调用关系

算法从当前投影往前估算，默认保留约 20000 个近期 token，再摘要较旧部分。优先按用户消息跨度切分；一个跨度本身过大时，可从 assistant 消息切开，将前缀单独摘要。合法边界不会落在 toolResult 上，否则模型会看见结果却失去发起调用的 assistant。

一次压缩追加 CompactionEntry，记录 summary、firstKeptEntryId、tokensBefore 和可用的 usage，还保存压缩边界的系统提示与工具检查点。后续上下文由该检查点、摘要、保留区间和新 entries 重建。原始历史继续存在，保留范围为空时 firstKeptEntryId 指向该压缩 entry 自身。


## 重复压缩处理的是投影，不是原始文件切片

再次压缩时，从上次保留边界接着摘要，并把上一份摘要作为迭代上下文；不应从上一条 compaction 的物理位置盲目切片。被 context_edit 省略的原始条目不参与切点、摘要和窗口估算，tokensBefore 也要按重建后的实际投影计算。

默认摘要保留目标、约束、进展、关键决定和下一步，压缩摘要还包含继续任务必需的关键背景。序列化不包含 thinking 块，并截断过长工具结果以控制摘要请求体积。读写文件清单会在 Pi 默认摘要间累计；扩展自供摘要的 details 需要由扩展自己维护。


## 离开分支时，摘要负责交接另一条路径

/tree 导航可把从旧 leaf 到共同祖先之间、不会出现在新活动路径中的工作做成 branch_summary。它的 parentId 指向新分支续接位置，fromId 记录离开的旧 leaf。这个摘要解决切换路径后的信息交接；compaction 解决当前路径的窗口压力，两者不能互相替代。

扩展可通过 session_before_compact 取消或自供摘要，通过失败事件观察压缩终态，也可参与树导航摘要。无论默认还是自供摘要，都应保留能验证的完成事项、未解决问题和原始证据位置；摘要只是工作交接材料，无法保证模型没有遗漏或曲解。


## 实验：手工摘要探针：比较压缩与离开分支

用内存 SessionManager 验证摘要 entry 的上下文重建语义；手工提供摘要，隔离掉模型质量和计费变量。

运行条件：离线（需预先安装固定版本依赖）

1. 在已准备 @earendil-works/pi-coding-agent@1.5.0 的临时 Node 项目保存 summary-projection.mjs。
2. 运行代码：第一份会话追加 compaction 并保留新消息；第二份会话从共同祖先建立带摘要的新分支。
3. 核对原始哨兵记录仍可读取，却不直接进入新上下文；再检查 firstKeptEntryId、parentId、fromId 的含义。

```javascript
import assert from 'node:assert/strict';
import { SessionManager } from '@earendil-works/pi-coding-agent';
const user = content => ({ role: 'user', content, timestamp: 0 });
const compacted = SessionManager.inMemory();
const oldId = compacted.appendMessage(user('OLD_RAW_SENTINEL'));
const keptId = compacted.appendMessage(user('continue with the query test'));
const compactId = compacted.appendCompaction('Earlier work chose SQLite.', keptId, 1234);
const projected = JSON.stringify(compacted.buildSessionContext().messages);
assert.equal(compacted.getEntry(oldId).message.content, 'OLD_RAW_SENTINEL');
assert.equal(compacted.getEntry(compactId).firstKeptEntryId, keptId);
assert.ok(projected.includes('Earlier work chose SQLite.'));
assert.ok(projected.includes('continue with the query test'));
assert.ok(!projected.includes('OLD_RAW_SENTINEL'));
const branched = SessionManager.inMemory();
const common = branched.appendMessage(user('shared goal'));
const oldLeaf = branched.appendMessage(user('LEFT_RAW_SENTINEL'));
const summaryId = branched.branchWithSummary(common, 'Approach A was explored.', undefined, true);
const summary = branched.getEntry(summaryId);
assert.equal(summary.parentId, common);
assert.equal(summary.fromId, oldLeaf);
assert.equal(branched.getEntry(oldLeaf).message.content, 'LEFT_RAW_SENTINEL');
const newContext = JSON.stringify(branched.buildSessionContext().messages);
assert.ok(newContext.includes('Approach A was explored.'));
assert.ok(!newContext.includes('LEFT_RAW_SENTINEL'));
console.log(JSON.stringify({ compactionRebuilt: true, branchSummaryLinked: true, rawHistoryPreserved: true }));

```

### 预期结果

- compaction 投影包含手工摘要与保留的新消息，不包含旧哨兵原文；旧 entry 仍存在。
- branch_summary 的 parentId 为共同祖先，fromId 为离开的 leaf，新路径只携带它的摘要而不复制旧路径原文。

验收：所有断言通过且退出码 0；能够解释“模型没看见原文”和“原文已经删除”的区别。

固定版依赖已准备后无需网络或模型账户。本探针不执行 /compact、不调用摘要模型，不验证自动切点、真实 token 估算或 LLM 摘要质量；这些需要另做 provider 集成测试。

## 容易混淆的地方

- 以为 reserveTokens 就是摘要请求固定输出上限。
- 为了省 token，从 toolResult 截断，拆散工具调用与结果。
- 把分支摘要当作合并两条完整历史，或宣称压缩删除了原始记录。

## 版本变化

完整按当前规范投影、系统检查点和摘要预算讲解；保留仍成立的 16384/20000 默认值，同时说明它们与按模型设置、摘要输出上限的区别。
