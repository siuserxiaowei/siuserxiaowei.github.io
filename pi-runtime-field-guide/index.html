Agent 的难点从来不是“让模型再调用一次 API”。

模型想继续、工具会失败、上下文会溢出、进程会崩之后。

Pi 的答案：把循环、错误、上下文与历史做成明确数据结构，而不是藏在一个“run()”黑盒里。

本指南的答案：每章先留三个问题；源码结论链接固定 commit，版本变化单独记账。

01 / FIVE FINDINGS

带着五个判断
继续读源码

01

“停止”不是一个布尔值

模型 stopReason、tool terminate、finishTurn、steering 与 follow-up 队列共同决定一轮是否真的结束。旧课程的 shouldStopAfterTurn 需按迁移记录更新。

02

工具失败 ≠ 供应商失败

网络与限流可透明退避；带副作用的工具不能无脑重试。幂等键、重放策略与副作用分类必须在模型之外。

03

压缩是上下文重建

Pi 保留 recent tail、摘要旧内容，并守住 tool call/result 边界。它不是粗暴截断消息数组。

04

树让回退自然发生

在 8 月 26 日冻结源码中，Pi 在单一 JSONL 内用 parentId 构成 entry tree；DSH 让单 session 保持线性、跨 session fork 成谱系。

05

安全边界不能靠提示词

Pi 官方明确没有内建权限系统。Hook 负责可拦截，sandbox、policy、approval、secret broker 与审计仍要外置。
